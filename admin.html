ADMIN PANEL DESIGN ============================================================ Panel title: PingMe Communication Centre Branding: - Use the official PingMe logo. - Brand tagline: ONE SCAN. INSTANT CONNECTION. - Premium, clean, modern and mobile-friendly design. - Use PingMe blue, white and cyan, with restrained pink accents. - Keep the screen uncluttered and easy for a non-technical admin. Review recipient count and sending eligibility. 7. Confirm and send. 8. Review message history and delivery status. ============================================================ 3. CUSTOMER SELECTION ============================================================ Provide a searchable customer dropdown/list. Search by: - Customer name. - Mobile number. Show these customer statuses: - Active. - Testing. - Inactive. Requirements: - Do not hide Testing or Inactive customers. - Allow selection of one customer. - Allow selection of multiple customers. - Provide Select All for the currently filtered list. - Show selected-recipient count clearly. - Show customer name, mobile number and account status. - Provide a separate option to enter an unregistered mobile number. - Validate mobile number format and country code. - Require appropriate consent before sending to a contact. - Warn before sending to an Inactive customer. - Do not silently skip recipients who cannot receive the selected message. Before sending, show a confirmation such as: "You are about to send this message to 12 recipients. Continue?" ============================================================ 4. TEMPLATE MANAGEMENT ============================================================ The Communication Centre should: - Display the seven templates in a simple, clear list. - Show each template's category and approval status. - Distinguish Approved, Pending, Rejected and Paused templates. - Use the actual Meta-approved template name and language. - Use the actual approved variable count and order. - Populate customer-specific variables automatically where data exists. - Allow the admin to edit only fields/content that the approved template format permits. - Do not change an approved Meta template's structure in the local panel and assume Meta will accept it. - Keep a preview of the final message before sending. - Keep the existing pingme_instant_alert template separate and untouched. If a proposed template is not yet approved: - Mark it clearly as Draft or Awaiting Meta Approval. - Do not present it as ready for out-of-window sending. - Do not attempt to send it as an approved template. ============================================================ 7. MESSAGE PREVIEW AND BRANDING ============================================================ - Show a WhatsApp-style message preview. - Display the PingMe logo in the Admin panel header. - Use PingMe branding in optional promotional image artwork. - Do not assume a logo displayed in the Admin panel is automatically included in a plain-text WhatsApp message. - Provide optional image attachment only where the existing sender and WhatsApp message type support it. - Show the final recipient-specific message preview where practical. - Ensure variable values are filled before sending. - Flag missing variables rather than sending broken placeholders such as {{1}}. ============================================================ 8. SENDING RULES AND SAFETY ============================================================ Before sending: - Check recipient number validity. - Check consent where required. - Check whether the customer-service window is open for free-form messages. - Check whether the selected Meta template is approved and active. - Check the template language and variable count. - Check required variables are populated. - Show recipient count and any recipients who cannot receive the message. - Ask for final admin confirmation. Sending behaviour: - Preserve the existing working WhatsApp API integration. - Use the approved template send path for out-of-window template messages. - Use free-form messages only when the service window is open and permitted. - Do not send marketing content as Utility. - Do not silently change template categories. - Do not send to unconsented marketing recipients. - Do not expose access tokens, App Secrets or webhook secrets in the browser/Admin UI. ============================================================ 9. MESSAGE HISTORY ============================================================ Provide a message history table with: - Date and time. - Customer name. - Mobile number (mask where appropriate). - Template/message name. - Message category. - Sending mode (template or free-form). - Meta message ID, where available. - Status: Submitted, Sent, Delivered, Read, Failed or Pending, as supported by actual webhook data. - Failure reason, where available. Important: - Do not label an API-accepted message as Delivered. - Update delivery status from WhatsApp webhook events. - Handle duplicate webhook events safely. - Avoid duplicate credit deductions. - Keep an audit record of who sent the message and when. ============================================================ 10.
